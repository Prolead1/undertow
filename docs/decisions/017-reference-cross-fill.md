# ADR 017 — Cross-fill a thin reference symbol from the densest one

**Status:** accepted (implementation and export)
**Affects:** `src/undertow/data/fetchers/reference.py` · `src/undertow/data/schemas.py` (reference description) · data `CONTRACTS.md` §4.6 · `docs/data_dictionary.md` · `docs/schema_notes.md`
**Raised by:** training-readiness follow-up (`bug-data-reference-cross-fill`)

## Context

The reference fetcher pulls **two** Binance symbols (data `PLAN.md` §7: `ETHUSDT`
primary and deepest, `ETHUSDC` as the thinner cross-check) and reindexes each onto
a complete 1-minute grid. Historically a missing bar was **forward-filled** from
that symbol's own last observed close and flagged.

## Problem

The thin cross-check has multi-month exchange outages. Binance's `ETHUSDC` bulk
archives for 2022-10 … 2023-02 are absent (HTTP 404), and the REST fallback
returns nothing, so `ETHUSDC` is missing **236 450 minutes (164.2 days)** across
two disjoint runs within a 2022-09-29 → 2023-03-24 span. Forward-filling each
symbol independently freezes `ETHUSDC` at one stale close for that whole period
— the stored stream had **only 2 distinct closes across those 236 450 bars**
(`1338.12` throughout), while the deeper `ETHUSDT` tracked the market from
~$1336 to ~$1792 over the same window.

That makes the cross-check useless for `compare_symbols`, and it poisons anything
computed on `ETHUSDC` alone (e.g. regime labels, whose volatility collapses to
zero over the flat stretch).

## Decision

`forward_fill_klines` cross-fills **secondary** symbols from the **densest**
symbol (the one with the most observed bars; ties break on the symbol name):

- The source's *effective* close at each grid minute — its observed close, else
  its own forward-filled close — is computed once.
- A secondary symbol's missing bar becomes `source_effective_close * scale`,
  where `scale` is the median observed close ratio (own / source) over shared
  minutes (default `1.0` when there are fewer than two shared observations), so a
  persistent basis is preserved, not just the shape.
- The **densest** symbol itself is never cross-filled (it stays observed/forward
  filled). The fetcher has no separate "primary" parameter, so this protects the
  densest series, which is `ETHUSDT` in the pinned feed; a config that fetched a
  denser cross-check would protect that one instead.
- Cross-filled bars are flagged `is_gap_filled = True` (they are not observed by
  their own symbol), counted in a new `GapStats.n_cross_filled`, and reported via
  `FetchResult.warnings`.
- `cross_fill: bool = True` is a keyword-only default; `cross_fill=False` recovers
  the old per-symbol forward-fill.

## Consequences

- Once the reference stream is regenerated (`--force` pull from the cached raw
  responses + `snapshot`; `data/` is gitignored), `ETHUSDC` tracks `ETHUSDT`
  through the outage: 236 450 cross-filled bars, ~318 870 distinct closes instead
  of 2, within ~0.5 bps of the primary (their persistent basis). `ETHUSDT`'s own
  80-minute outage is unchanged (forward-filled). Until that regeneration runs,
  the on-disk parquet still holds the old frozen values.
- The cross-scale is a window-global median, so it is estimated from the whole
  window (including minutes after a given gap). It is a single constant per
  symbol (not a per-bar quantity), so the effect on any causal consumer is a
  fixed level adjustment — negligible for a stablecoin pair — but it is not
  strictly causal and is recorded here.
- Cross-filled bars remain `is_gap_filled = True`, so `check_reference_coverage`
  and T12's regime gap-window warning still surface that ~15% of `ETHUSDC` is
  synthetic — the warning is now about *provenance*, and the fills are no longer
  zero-return, so the volatility bias it describes is largely gone. The simulator
  consumes the primary (`DataConfig.reference_symbol`, ADR-014), so training is
  unaffected either way.
- The reference stream is regenerated by a `--force` pull (no network: the raw
  fetches are cached) followed by a `snapshot` to rebuild the tape/regimes.
- Rejected alternatives:
  - *Drop the cross-check when it has long gaps.* Loses the `compare_symbols`
    sanity check entirely.
  - *Interpolate `ETHUSDC` between its own endpoints.* Look-ahead-free but
    fabricates a straight line through a six-month move; the sibling's real
    contemporaneous path is strictly better.
  - *Use `ETHUSDC` to fill `ETHUSDT`.* Inverts the primary/cross-check priority;
    the plan makes `ETHUSDT` primary precisely because the `USDC` pair is thinner.

## Notes

- The pure grid/fill logic (`forward_fill_klines` + helpers + `GapStats`) sits in
  `fetchers/reference.py`, which is large; if it grows further it should move to
  its own module (e.g. `fetchers/gapfill.py`) re-exported from `reference`.
